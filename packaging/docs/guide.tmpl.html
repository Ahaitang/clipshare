1. 这是什么

同一个局域网内的几台电脑，在一台机器上复制，另一台的剪贴板随即变成同样内容， 并且每台机器都留有一份带来源标记的历史，随时可以从历史里翻出前几条重新复制。

  • 零依赖：单个可执行文件，静态编译（CGO_ENABLED=0），不需要装运行时。
  • 无中心节点：每台机器既是服务端也是客户端，两台就能用，多台自动成网。
  • 只同步纯文本：图片、文件、富文本不在范围内（v1 的明确取舍）。

2. 安装

Ubuntu / Debian

sudo dpkg -i clipshare_0.1.0_amd64.deb
systemctl --user daemon-reload
systemctl --user enable --now clipshare

装好后程序常驻托盘、开机自启，并自动把 Ctrl+Alt+V 注册成历史快捷键 （GNOME 自定义快捷键，槽位名 clipshare）。

剪贴板读写依赖系统命令，按会话类型二选一：

sudo apt install xclip        # X11（或 xsel）
sudo apt install wl-clipboard # Wayland

Windows 10 / 11

双击 clipshare-0.1.0-windows-setup.exe，一路下一步即可。安装包会：

  • 装到 Program Files\clipshare，创建开始菜单快捷方式；
  • 登记登录自启（HKLM Run）；
  • 自动放行防火墙入站 TCP 47100（不放行就只剩单向同步）；
  • 写入「程序和功能」里的卸载项。

另有免安装版 clipshare-0.1.0-windows-amd64.zip（含 install.ps1 / 卸载.ps1）。 Windows 版编译为 GUI 子系统，启动不会有控制台黑窗；日志写在 %APPDATA%\clipshare\clipshare.log。

3. 第一次配置：一条邀请码

第一次配置原本要做两件事：抄 12 位房间码、以及在禁多播的网络里手填对方地址。 现在它们被压成一条可复制的邀请码：

clipshare1:2mnsn82k6b62@172.26.81.147:47100
   └ 版本前缀  └ 房间码      └ 对方地址:端口

第一台机器（确定房间）：

clipshare invite       # 直接打印邀请码
clipshare init         # 或者交互式选择「我是第一台机器」

新机器（任选一种）：

clipshare join 'clipshare1:2mnsn82k6b62@172.26.81.147:47100'

或者打开本地历史页 → 展开「房间与邀请」→ 粘贴邀请码 → 点「加入房间」。 两种方式都会写入 roomKey 与 seeds，并自动让正在运行的实例重启生效。

邀请码等于房间钥匙。拿到它的人可以读到你们同步的剪贴板内容，也可以写入。 它只包含房间码和地址、不含设备标识，但仍应按「发给可信同事」的尺度处理。

4. 日常使用：Ctrl+Alt+V 取用历史

按下 Ctrl+Alt+V 会弹出历史选择窗口：

  • 直接打字即过滤，匹配内容与来源节点名；
  • ↑↓ 移动、PgUp/PgDn 翻页、 Enter 取回、Esc 取消；
  • 鼠标单击某一行＝取回该条；按住顶部标题条可以拖动窗口（右侧有一排小点作为提示）， 位置会被记住，下次弹回同一处；
  • 取回只写本机剪贴板，不会广播给其他机器（避免把旧内容推给别人）。

Linux 的快捷键是怎么来的：程序启动时自己登记到 GNOME 自定义快捷键 （追加到你的列表，不覆盖 flameshot 等已有项）；组合键已被别的程序占用时不会抢占，只在日志里提示。 非 GNOME 桌面不自动登记，请自行把某个组合键绑到 clipshare pick。

5. 本地历史页

http://127.0.0.1:47101/ui（端口 = 同步端口 + 1）。页面只绑回环地址、无鉴权， 提供搜索、行内「复制到本机」、清空历史、重启，以及房间与邀请面板。

7. 工作原理

  • 触发：轮询本机剪贴板（默认 400ms），内容变化才产生条目。
  • 去重与回环抑制：同内容只保留一条；程序自己写入剪贴板的内容会被标记为「已见」， 不会被误判成用户复制而再次广播。
  • 广播：并发 POST 给所有同房间节点，失败不重试（剪贴板内容有过期语义， 延迟重发反而造成时序错乱）。
  • 接收：校验 Bearer 房间密钥与 X-Room 房间标识， 去重命中直接 202 丢弃；时间戳一律用接收方本地时间，规避跨机时钟漂移。
  • 发现：mDNS 组播自动发现；禁多播的网络用 seeds 互指并周期性探活。

8. 排障

现象多半是怎么办
一端能收到、另一端收不到收到的那端防火墙没放入站 Windows：管理员 PowerShell 执行
New-NetFirewallRule -DisplayName clipshare -Direction Inbound -Protocol TCP -LocalPort 47100 -Action Allow
Linux：sudo ufw allow 47100/tcp
日志显示「当前无可用节点」节点发现没成功 ① 两边 roomKey 一致 ② seeds 的 IP:端口正确 ③ 端口入站已放行
托盘里没有图标GNOME 缺 AppIndicator 扩展 加 --no-tray，改用历史页；日志里会打印实际地址
启动报端口被占用已有实例或别的程序占了 47100 用 --port 换一个，两台一起改
按了 Ctrl+Alt+V 没反应快捷键未登记或被别的程序占用 journalctl --user -u clipshare -n 20 看「快捷键」那行
启动后第一次复制没同步旧版本缺陷（已修） 升级到当前版本

9. 安全边界

  • 明文传输：局域网内可被嗅探。房间密钥只解决「谁能接入」，不提供加密。
  • 同房间的半信任模型：任何拿到房间码的人都能读同步流，也能往你的剪贴板写入内容。
  • 历史默认明文落盘：history.json；persist: false 可关闭持久化。
  • 房间码强度：首启生成 12 位（约 59 bit）。/v1/health 与 mDNS 会公开它的 sha256 前 12 位， 所以短房间码（例如 6 位≈30 bit）可被离线爆破——不要改短。
  • 历史页只绑回环：127.0.0.1，无鉴权，不要改成对外监听。

10. 附录：命令与配置

命令行

命令作用
clipshare前台启动（托盘常驻）
clipshare --no-tray无托盘模式，用本地历史页
clipshare invite打印本机邀请码
clipshare join '<邀请码>'加入别人的房间并重启生效
clipshare init交互式首次配置
clipshare pick弹出历史选择窗口（快捷键调用的就是它）
clipshare status打印同步状态：房间、与几台同步中、暂停、历史条数、最近错误
clipshare --version版本号（Windows GUI 版无控制台输出）

常用参数

参数说明
--room房间码，覆盖配置（多台必须一致）
--port同步端口，默认 47100；历史页用 port+1
--seed静态节点地址 host:port，可重复；禁多播时用
--mdns=false关闭组播发现，只连 seeds
--no-persist历史不落盘
--config-dir指定配置目录（多实例测试用）
